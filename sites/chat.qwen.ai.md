# دليل موقع: chat.qwen.ai (Qwen Studio)

> دليل تشغيل مُتحقَّق منه بالتنفيذ الفعلي — لا تخمين. آخر تحقق: 2026-08-05 على Chrome 150 عبر وضع الإضافة.
> **المدخل المفضل:** استخدم أمر `acp qwen "<question>"` للاستشارات بسطر واحد والأرشفة التلقائية بدلاً من تركيب أوامر `acp web call` يدوياً.
> اقرأ [WEBBRIDGE.md](../WEBBRIDGE.md) أولاً لفهم الأوامر العامة والحارس وقاعدة بيانات `qwen.db`.

## المتطلبات

| المتطلب | لماذا |
|---|---|
| `acp web allow chat.qwen.ai` | بدونه كل أمر يرجع `deny` |
| **وضع الإضافة** (`--via extension` أو auto مع منبر شغّال) | الموقع يحتاج تسجيل دخول؛ وضع الإضافة يستخدم بروفايل المستخدم اليومي وهو **مسجَّل دخوله فعلاً** |
| وضع مباشر (`--via direct`) | يفتح الموقع لكن **غير مسجَّل دخول** — صالح للقراءة العامة فقط |

## المحدِّدات الثابتة (استخدمها، لا أرقام `@eN`)

مراجع `@eN` تُولَّد مع كل `snapshot` وتموت عند أي انتقال. هذه محدِّدات CSS ثابتة تحققت منها:

| العنصر | المحدِّد | ملاحظة |
|---|---|---|
| محرّر الرسالة | `textarea` | وحيد في الصفحة |
| زر الإرسال | `.send-button` (و`aria-label="Send"`) | **زر الصوت نفسه يتحوّل إلى Send بعد الكتابة** |
| نص الرد | **أعلى** عنصر `[class*=markdown]` — انظر التحذير | 0 عناصر في صفحة جديدة |

> ⚠️ **مطبّ يكذب عليك بصمت:** `[class*=markdown]` مطابقة **جزئية** تصيب الحاويات المتداخلة والفقرات والأسطر
> المفردة — في محادثة من ثلاث رسائل رصدنا **179 عنصراً مطابقاً**. فأخذ «آخر عنصر» يعطيك آخر **ورقة صغيرة**
> لا الرد الكامل: نجح مع رد من كلمة واحدة («باريس») وبتر رداً من عشرة أسطر إلى سطر واحد.
>
> الاستخراج الصحيح — صفِّ ما ليس داخل عنصر مطابق آخر، ثم خذ الأخير:
> ```js
> (()=>{const all=[...document.querySelectorAll('[class*=markdown]')];
>  const tops=all.filter(e=>!e.parentElement||!e.parentElement.closest('[class*=markdown]'));
>  return tops.length?tops[tops.length-1].innerText.trim():''})()
> ```
> والحيلة نفسها تعطيك أي رسالة سابقة: `tops[0]` أول رد · `tops[1]` الثاني · وهكذا.
| اسم النموذج الحالي | زر أعلى الصفحة نصّه اسم النموذج | مثال: `Qwen3.8-Max` |

## الوصفة القياسية للاستشارة

> **وضع التفكير يملكه المستخدم من ويدجت المتصفح — لا يغيّره الوكيل من تلقاء نفسه.**
> الموقع يحفظ اختيار المستخدم لحسابه، والوكيل يقرأ القيمة للعلم فقط ولا يكتبها إلا بطلب صريح.
> للسياق عند الإبلاغ عن البطء: `Fast` وسيط 3.7s وأبطأ 4.9s · `Auto` وسيط 12.0s وذيل يصل 90.6s.

```bash
# 0. افتح محادثة مؤقتة ثم ثبّت Thinking = Fast (خطوة إلزامية في الوصفة)
acp web call navigate --url "https://chat.qwen.ai/?temporary-chat=true" --session qwen

# 1. صفحة جديدة نظيفة (أضمن من زر New Chat) — للمحادثات العادية فقط
acp web call navigate --url https://chat.qwen.ai/ --session qwen

# 2. اكتب السؤال
acp web call fill --selector "textarea" --value "سؤالك هنا" --session qwen --write

# 3. أرسل — يتطلب إذناً بشرياً صريحاً (انظر التحذير أدناه)
acp web call click --selector ".send-button" --session qwen --write --allow-submit

# 4. انتظر الاكتمال (عبر أمر wait الشرطي بدلاً من الانتظار الزمني)
acp web call wait --gone "[aria-label='Stop']" --session qwen

# 5. اقرأ الرد
acp web call evaluate --session qwen --write \
  --code "(()=>{const a=[...document.querySelectorAll('[class*=markdown]')];const t=a.filter(e=>!e.parentElement||!e.parentElement.closest('[class*=markdown]'));return t.length?t[t.length-1].innerText.trim():''})()"
```

### البصمة المعمارية للواجهة (UI Fingerprint)
لحماية الجلسة من التغييرات المفاجئة في تصميم الصفحة عند إعادة تصميم الموقع، التقط بصمة العناصر أولاً ثم فحصها:
```bash
acp web fingerprint capture --session qwen   # التقاط البصمة الأساسية وتخزينها
acp web fingerprint check --session qwen     # فحص تطابق البصمة مع الواجهة الحالية
```

### كيف تعرف أن الرد اكتمل
انتظر شرطياً باستخدام أمر `wait` حتى يعود زر الإرسال إلى `Send` أو يختفي زر `Stop`:
```bash
acp web call wait --gone "[aria-label='Stop']" --session qwen
```
أمر `wait` يفحص الصفحة تلقائياً كل 250ms حتى يتحقق الشرط أو تنتهي المهلة مع إرجاع تقرير تشخيصي دقيق عند التوقف.

## وضع التفكير — أهم مقبض للسرعة
حقل `Thinking` بجانب المحرّر، وقيمه: **`Auto`** (الافتراضي) · **`Thinking`** · **`Fast`**.
هو المتحكم الأول في زمن الرد؛ في وضع `Auto` قد يقفز سؤال واحد من 6 ثوانٍ إلى 90 ثانية لأن النموذج قرّر التفكير.

**اقرأ القيمة الحالية قبل أن تضبط شيئاً** — التفضيل يبقى محفوظاً لحساب المستخدم، فالتبويب الجديد غالباً
يفتح على آخر قيمة اختيرت (تحققنا: تبويب جديد تماماً فتح على `Fast` بلا ضبط):
```bash
acp web call evaluate --session qwen --write \
  --code "(()=>{const s=document.querySelector('.ant-select-selection-item');return s?s.innerText.trim():null})()"
```
`.ant-select-selection-item` هو محدِّد القيمة المعروضة (الواجهة مبنية على Ant Design).

**تحذير من مطبّ:** خيارات هذه القائمة **لا تظهر في `snapshot`** (بلا اسم وصول)، فمحاولة اختيارها بـ `--ref` تفشل
بصمت وتبقى على القيمة السابقة. الطريقة الناجحة: حدّد العنصر بنصّه الحرفي عبر `evaluate` ثم انقر على إحداثياته.

```bash
# 1. افتح القائمة (ref حقل Thinking من snapshot)
acp web call click --ref @eN --session qwen --write
# 2. اقرأ إحداثيات الخيار المطلوب
acp web call evaluate --session qwen --write --code \
  "(()=>{const el=[...document.querySelectorAll('*')].filter(e=>(e.innerText||'').trim()==='Fast'&&e.children.length===0).pop();const r=el.getBoundingClientRect();return JSON.stringify({x:r.left+r.width/2,y:r.top+r.height/2})})()"
```
ثم انقر على تلك الإحداثيات (أو استعمل `--selector` إن وُجد محدِّد CSS ثابت). تحقّق دائماً بعدها أن الحقل يعرض القيمة الجديدة.


## ويدجت وضع التفكير — الحقائق المُثبَتة على الصفحة الحيّة (2026-08-05)

لم تعد الويدجت تُدار بلقطات إحداثيات. مالكها الوحيد `src/web/widgets/qwen-composer.ts`،
وواجهته `readMode / readModel / ensureMode`. ومن سطر الأوامر:

```bash
acp qwen mode                 # اقرأ الوضع والنموذج وبأي محدِّد طابقا
acp qwen mode Fast            # اضبط وضعك أنت، بقصد صريح
acp qwen "<سؤال>" --mode Thinking   # لهذه الاستشارة فقط، ثم يُعاد ما كان
```

**المحدِّدات الحقيقية** (بترتيب السلّم — الأصناف الدلالية للموقع أولاً، وأصناف Ant احتياطاً):

| الغرض | المحدِّد |
|---|---|
| جذر ويدجت التفكير (النقر عليه يفتح القائمة) | `.qwen-select-thinking` |
| الحاوية | `.qwen-thinking-selector` |
| صفوف القائمة القابلة للنقر | `.ant-select-item-option[title="Fast"]` |
| النموذج | `[class*=model-selector-text]` |

### ثلاثة مصائد كلّفت وقتاً، ولن تُخمَّن من قراءة الشيفرة

1. **`[role=option]` هنا عُقد مرآة عرضها صفر وغير محاذية للصفوف.** مرآة «Fast» كانت أعلى
   الصف الحقيقي بـ 36 بكسل، أي فوق «Thinking» — فالنقر على المحدِّد «الأدلّ دلالياً» كان
   يعيد اختيار الوضع الذي نحاول مغادرته. القاعدة: **الهندسة تقرّر ما يُنقر، والدلالة تقرّر ما يعني**.
   الوحدة ترفض الآن أي هدف أبعاده أقل من 2×2.
2. **`.ant-select-selector` يقرأ الوضع بصحة لكنه لا يفتح القائمة.** القراءة والتشغيل قدرتان
   مختلفتان؛ السلّم يبدأ بالجذر لا بعقدة داخلية.
3. **الوضع تفضيل يخصّ الحساب، لكن حفظه غير متزامن.** تبويب فُتح مباشرة بعد تبديل مُتحقَّق منه
   قرأ الوضع القديم، ثم قرأ الجديد بعد ثوانٍ. لذلك تنتظر الوحدة 1.5 ثانية بعد أي تبديل ناجح:
   القيمة المعروضة ليست القيمة المحفوظة.

### قواعد ملزمة

- **فشل ضبط الوضع خطأ يوقف الاستشارة، قبل كتابة حرف في المحرّر.** الوضع يحدد جودة الجواب
  ومهلة الانتظار وما يُسجَّل في الأرشيف؛ و«أكمل بالوضع الحالي» تدريب على تجاهل الانكسار.
- **لا نقرات برمجية `element.click()`** — كل تفاعل بإدخال موثوق عبر CDP، ولوحة المفاتيح
  احتياطياً (لا تحتاج إحداثيات أصلاً).
- **الوضع ملك المستخدم.** يُعدَّل عند الطلب فقط ويُعاد قبل أي إنهاء. وضمانة الإعادة ليست
  `finally` — بل علامة على القرص في `~/.acp/web-widget-restore.json` يقرأها أول تشغيل تالٍ،
  لأن `process.exit` يقفز فوق `finally` (وهذا ما ترك الحساب على `Thinking`).
- محدِّدات الويدجت مُسجَّلة في نظام البصمة، فتغيّر الواجهة يُكتشف عند `fingerprint check`.


## حقائق مقاسة على الصفحة الحيّة — أُخذت بالرصد لا بالتخمين (2026-08-05)

### 1. زر الإرسال **غير موجود** ما دام المحرّر فارغاً

فحص الصفحة قبل الكتابة يعيد `{"missing": true}` لـ`.send-button`. يظهر الزر بعد
~40 مللي من وصول النص، **مفعّلاً مباشرة**. أي أن `click('.send-button')` مباشرة بعد
`fill` كان ينقر عنصراً لم يُخلق: تفشل النقرة، ننتظر مهلة ثانيتين، ثم ينجح Enter الاحتياطي.
**٣٢٠٠ مللي من زمن الإرسال كانت هذه، ونُسبت للموقع.**
القاعدة: `waitFor({selector: '.send-button'})` قبل النقر — تكلفتها ٤٠ مللي.

### 2. كاشف الاكتمال: زر `Stop` هو الإشارة، لا زر `Send`

رصد جواب يبثّ فعلاً (قصة أربعة أسطر، وضع Fast، عيّنة كل ١٠٠ مللي):

| اللحظة | الحالة |
|---|---|
| 3913ms | ظهر `Stop` · النص 0 حرف |
| 5295ms | أول 13 حرفاً (تفكير 1.4s قبل أول حرف) |
| 5295→7195ms | نموّ متصل بدفعات كل 100–350 مللي حتى 270 حرفاً |
| 7942ms | اختفى `Stop` · عاد `Send` **معطّلاً** |

**«انتهاء كاذب» في هذه العيّنة: صفر** — `Stop` بقي حاضراً طوال البث في Fast.
لذلك نافذة الثبات لا تحتاج أن تكون طويلة في Fast؛ وهي تتكيّف الآن مع أطول فجوة
نموّ لُوحظت فعلاً (×2، بحد أدنى 500 مللي وسقف 2s في Fast و4s في Thinking).
**تنبيه منهجي:** الأرقام السابقة كانت مضبوطة على أجوبة من رمز واحد («42»)، وهي حالة
منحطّة بلا بثّ ولا فجوات — لا يجوز الضبط عليها.

### 3. للحساب **حدّ استخدام يومي** — خلافاً لما كان مفترضاً

النص الحرفي الملتقط من الصفحة:

> `You have reached the daily usage limit. Please wait 8 hours before trying again.`

هذا ليس عطلاً عابراً: إعادة المحاولة تطرق باباً مغلقاً. صار `rate_limit` **غير قابل
لإعادة المحاولة**، ويُطبع الوقت المطلوب. والإشعار كاملاً يُحفظ في السجل لأن التوست
يختفي خلال ثوانٍ ولا يبقى منه إلا شظية لا تُفرّق بين حدّ حقيقي وإنذار كاذب.

### 4. زمن الاستشارة بعد الإصلاحات (Fast، تبويب مُعاد)

| المرحلة | قبل | بعد |
|---|---|---|
| قياس الأساس | 1500ms ثابتة | **4ms** (تُتخطّى بلا إعادة تحميل) |
| تأكيد الكتابة | 900ms ثابتة | ~215ms (شرط لا نوم) |
| الإرسال | ~3200ms (نقرة فاشلة + مهلة) | ~650ms |
| **الإجمالي** | **5.7s** | **3.0–3.6s** |


## الانتظار — بدائية واحدة تحمل القاعدة المدرَّبة

```bash
acp web call wait --stable "[class*=markdown]" --busy "[aria-label='Stop']"
```

**إشارتان لا واحدة:** النص توقّف عن التغيّر **و**مؤشر الانشغال اختفى. الثبات وحده لا
يفرّق بين بثّ متوقف مؤقتاً وبثّ منتهٍ — وهما متطابقان في النص، وهذا ما أرشف يوماً
شظية من ٥٢ حرفاً كإجابة كاملة. لذلك `--busy` **إلزامي**، و`--busy none` تجعل التخلّي
عنه اختياراً معلناً يُسجَّل لا صمتاً افتراضياً.

**النافذة تتكيّف:** ضعف أطول فجوة نموّ لوحظت فعلاً، بحد أدنى 500 مللي وسقف 4 ثوانٍ.
مقاس حيّاً: بثّ توقف 11.4 ثانية في منتصفه فطالبت القاعدة بـ4 ثوانٍ صمت — ولو كانت
النافذة ثابتة عند نصف ثانية لبُتر الجواب.

| الحالة | النتيجة |
|---|---|
| جواب مكتمل أصلاً | 0.5s · 4 استطلاعات |
| بثّ من أوله (3642 حرفاً) | 19.2s · انتهى فور اكتماله |

### الانتظار الأعمى — ممنوع بالتصميم لا بالنصيحة

`wait --until "false"` شرط لا يصدُق أبداً، أي نوم بثياب شرط. صار يُكشف ويُسجَّل:

```
{"neverTrue":true,"blindWait":true,"polls":23,"waitedMs":6009}
```

ومعه على مجرى الأخطاء **الأمر الجاهز البديل** — لأن الوكيل يختار المسار الأقل هشاشة،
فإن لم تكن الإشارة أسهل من الالتفاف بقي الالتفاف مغرياً.

وللتوقف الزمني المتعمّد أمر صريح: `sleep --ms <n> --reason "<لماذا>"` بسقف عشر ثوانٍ
والسبب إلزامي. والحصيلة كلها في `acp web waits`.

## بصمة الواجهة — إنذار مبكر قبل أن تنكسر الوصفة

```bash
acp web fingerprint capture --session qwen --selectors "textarea,.ant-select-selection-item"
acp web fingerprint check --session qwen     # {"match":true} أو قائمة ما تغيّر
```
بعد الالتقاط، كل `acp web call` يضيف `uiChanged` تلقائياً عند اختلاف البنية — **تحذير لا حاجز**، ولا يغيّر رمز الخروج.

**الدرس الذي كلّفنا محاولتين — اختر مؤشرات دائمة الوجود:**

| المؤشر | صالح للبصمة؟ | السبب |
|---|---|---|
| `textarea` · `.ant-select-selection-item` | ✅ | موجودان في كل حالات الصفحة (مُتحقَّق: تطابق في صفحة فارغة وفي محادثة ممتلئة) |
| `.send-button` | ❌ | لا يوجد أصلاً قبل الكتابة (زر الصوت يتحوّل إليه)، فيطلق إنذاراً في كل صفحة جديدة |
| `[class*=markdown]` · `input` · `button` | ❌ | أعدادها تتبع محتوى الصفحة لا بنيتها، فتقفز بين الفئات وتُغرقك بإنذارات كاذبة |

المحدِّد الممتاز **للوصفة** ليس بالضرورة مؤشراً جيداً **للبصمة**: الأول تريده دقيقاً للحظة الاستخدام، والثاني تريده
ثابتاً عبر كل الحالات. وإنذار يطلق دائماً يُدرّبك على تجاهله — وهو أسوأ من عدم وجوده.

## الاستمرارية — كل جلسة تعود إلى محادثتها

الجلسة تُخزَّن في `~/.acp/web-sessions.json` بحقل `resumeUrl` يحمل **رابط المحادثة** لا رقم التبويب فقط.
فإذا مات التبويب (أُغلق يدوياً أو أُعيد تشغيل كروم) يفتح النظام تبويباً جديداً على نفس الرابط ويعيد
`"resumed":"<url>"` في رده.

**مُتحقَّق منه (2026-08-05):** أُنشئت محادثة، أُغلق تبويبها من المتصفح، ثم نُودي نفس اسم الجلسة —
فعاد إلى `/c/5779d1a2-…` وظهرت الرسالة السابقة ورد «باريس» كاملاً.

- **انتظر 3–5 ثوانٍ بعد `resumed` قبل القراءة**: التاريخ يحتاج وقتاً للعرض (القراءة الفورية أعطت 0 رسائل ثم 4 بعد 4 ثوانٍ).
- الروابط غير القابلة للاستعادة تُستبعد تلقائياً: `/` و`/c/local` وأي رابط فيه `temporary-chat`.
- الرابط الحقيقي لا يُعطى إلا **بعد أول رسالة**، فلا تتوقع `resumeUrl` قبلها.

## المحادثة المؤقتة — للسؤال العابر فقط

**لا تُستعاد أبداً** بعد إغلاق تبويبها (`/c/local` لا يُحفظ على الخادم). استعملها حين يهمّ ألا يتلوّث السجل
ولا تهمّ الاستمرارية.

تُفعَّل بالرابط مباشرة — لا حاجة لأي نقر:
```bash
acp web call navigate --url "https://chat.qwen.ai/?temporary-chat=true" --session qwen
```
(البديل: زر **Temporary Chat** في أعلى الصفحة.)

علامات التفعيل: الصفحة تعرض «This chat won't appear in history and your messages will not be saved»، ويصبح الرابط
بعد أول رسالة `https://chat.qwen.ai/c/local` — أي `local` بدل معرّف محادثة، فلا شيء يُحفظ على الخادم.

**مُتحقَّق منه (2026-08-05):** أُرسل سؤال في الوضع المؤقت ووصل الرد، ثم فُحص السجل فلم يظهر فيه أثر —
بينما ظلّت محادثة عادية سابقة ظاهرة في نفس الفحص (شاهد ضبط يثبت أن السجل كان محمّلاً فعلاً).

## آداب الاستخدام
- المحادثة **العادية** تُنشئ مدخلاً في سجل المستخدم باسم مشتق من السؤال. لا تنشئ محادثات عادية بلا داعٍ.
- **الحذف من السجل يفعله المستخدم بنفسه.** لا يحذف الوكيل محادثات أو بيانات من حسابه؛ أقصى ما يفعله أن يفتح له
  المحادثة ويُظهر قائمتها ليضغط هو زر الحذف.

**التوصية:** ثبّت `Fast` لكل استشارة سريعة، ولا ترفعه إلى `Thinking`/`Auto` إلا لسؤال يحتاج استدلالاً فعلياً.

## أخطاء الموقع والإعادة التلقائية (Site Errors & Auto-Retries)

عند استدعاء `acp qwen` يتم فحص مناطق التنبيهات ونهاية نص الصفحة كل ~400ms لكشف أخطاء الخادم والقيود فور حدوثها دون الانتظار لمهلة الوقت الكاملة.

### كاشف أخطاء الموقع (`detectSiteError`)

- **أنواع الحالات وتدفقها**:
  - `site_error`: خطأ صريح من خادم Qwen (مثل "الخدمة غير متوفرة" / "Service Unavailable" / "too many requests" / "rate limit"). يتوقف الأمر فوراً مع تسجيل الحالة والمحدد في الأرشيف وإعادة المحاولة تلقائياً.
  - `stalled`: تعطل الإرسال؛ عند مرور 25 ثانية من النقر دون ظهور زر Stop ودون ظهور أي كتلة markdown أو خطأ موقع. يعتبر الإرسال تعثر ويتوقف الأمر مع إعادة المحاولة تلقائياً.
  - `timeout`: انتهاء المهلة الزمنية الكاملة أثناء توليد الإجابة. **لا يُعاد المحاولة تلقائياً** في هذه الحالة لمنع تكرار السؤال أثناء توليد النموذج.

- **سلوك الإعادة التلقائية (`--retries N`)**:
  - الخيار الافتراضي `--retries 1` يُعيد المحاولة مرة واحدة عند حدوث `site_error` أو `stalled` فقط بعد انتظار 3 ثوانٍ وإعادة تحميل محادثة الجلسة.
  - يُسجَّل كل محاولة كسطر مستقل في قاعدة البيانات مع تدوين رقم المحاولة `attempt: n` في الـ metadata.
